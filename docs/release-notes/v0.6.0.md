# tzro v0.6.0 Release Notes

**Release Date**: 2026-06-15

---

## ✨ New Features

- **Dynamic Local-Cloud Routing** — The engine now automatically decides whether to plan tasks locally or in the cloud based on a multi-gate decision tree: model mode override, privacy quarantine (restricted directories and sensitive keywords), cloud key availability, task complexity, and thermal pressure. No per-task configuration required.

- **Thermal Pressure Gating** — Cross-platform thermal monitoring (macOS, Linux, Windows) that reads CPU thermal state and factors it into routing and execution decisions. When the host is under heavy thermal load, the engine adapts its inference strategy to prevent overheating.

- **Agent App Package Manager** — Install, list, and uninstall Agent Apps packaged as `.tzroapp` archives. Each app can bundle tools, database migrations, and prompts. The package manager handles manifest parsing, file extraction, migration execution, tool registration, and clean uninstallation with full rollback.

- **OpenUI Dashboard** — A completely rebuilt web dashboard where the layout is server-generated as an OpenUI spec and rendered by a React adapter. Includes task spotlight, event log, system config viewer, workflow inspection, theme toggle (light/dark), and spec regeneration. The dashboard is served as a static build from the daemon.

- **Dynamic Workflow Orchestration** — Workflows can now run in "dynamic" mode where an LLM orchestrator decides the next child task after each step completes, continuing until the goal is achieved or an iteration limit (10) is reached. Replaces rigid pre-defined DAGs for open-ended goals.

- **SubagentChannel v3** — A transport-agnostic channel system for streaming real-time execution events (task lifecycle, node progress, edge thoughts, mutations) to external harnesses. Includes MCP, SSE, and plugin adapters with bidirectional tool dispatch for client-side tool execution.

- **Proactivity Escalation Gating** — Tools are now assigned proactivity levels (L0–L4) and checked against a workflow's approved ceiling before execution. If a tool exceeds the approved level, execution pauses and an escalation notification is sent for approval.

- **Response Resolver** — A three-tier binding resolution cascade (recursive key search → KV-line search → semantic LLM fallback) that deterministically extracts values from raw tool outputs for downstream variable interpolation, reducing inference costs for simple extractions.

- **PID Lock** — Daemon startup now acquires an exclusive file lock to prevent multiple instances from corrupting the shared database. Includes stale lock detection and clean diagnostic messages.

- **Service Registry** — Background agents (observer, sentinel, scheduler) are now managed through a declarative service registry with Start/Stop/List lifecycle, replacing hardcoded startup sequences.

## 🔧 Improvements

- **Semantic Validator Refactor** — The GBNF bridge node type has been renamed to "semantic_validator" with a two-pass extraction pipeline: Pass 1 uses free-form XML for maximum reasoning freedom, Pass 2 refines with grammar-constrained JSON for schema compliance.

- **Proactive Binding Splice (ADR-0030)** — High-confidence bindings are now stripped from the inference schema entirely and spliced back after extraction, eliminating model hallucination on values the system already knows deterministically.

- **MCP Singleton Guard** — Prevents duplicate MCP server registrations that could cause port conflicts and resource leaks.

- **Benchmark Matcher Improvements** — Enhanced parameter matching with relaxation policies for optional fields, numeric type coercion, case-insensitive slice matching, and single-element scalar/slice equivalence.

- **Cache Metrics** — Added hit/miss/eviction counters and average latency tracking to the inference cache layer.

- **Inference Metrics** — Added per-backend token throughput and latency tracking for both local and cloud inference backends.

- **Website Repositioning** — Landing page updated to reflect the AgenticOS positioning with Jumpdrive metaphor, new feature sections, and updated copy.
