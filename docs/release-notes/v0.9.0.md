# TZRO v0.9.0 Release Notes

**Release Date**: 2026-07-10

---

## ✨ New Features

- **Dual-Sidecar Inference** — The engine now runs two independent model sidecars concurrently: a fast router model for classification and navigation decisions, and a larger worker model for code generation and complex reasoning. All requests are transparently dispatched to the appropriate sidecar based on task type, with automatic fallback from router to worker when the router is unavailable.

- **Multi-Branch Evaluation** — At key decision points in execution graphs, the engine now generates multiple candidate approaches in a single inference call, evaluates each through speculative rollouts, and selects the highest-scoring path. A Speculation Fence prevents dangerous side effects during evaluation by classifying tools into real, simulated, or blocked categories based on their risk level.

- **Smart Context Budgeting** — Accumulated context for each execution step now uses tiered allocation that prioritizes the most relevant upstream outputs. Synthesis steps receive full untruncated context from critical predecessors, preventing information loss at the final summary stage.

- **Adaptive Probe Futility Detection** — Probes now detect when exploration is stuck (all initial steps returning errors) and abort early instead of burning through the entire step budget. The futility threshold scales dynamically with the probe's configured step budget.

- **Output Fingerprint Convergence** — Probes detect diminishing information gain when consecutive tool calls return identical results, and automatically transition from exploration to synthesis instead of grinding through redundant steps.

- **Pre-Flight Correction (PreFlect Hook)** — When a tool has a known failure mode captured as a corrective micro-skill from a previous execution, the correction is proactively injected into the node's instructions before it runs.

- **Hot-Swappable Model Management** — The engine can temporarily swap to a code-specialized model for generation tasks, then lazily restore the default model after completion — all transparent to the caller.

## 🔧 Improvements

- **Probe Performance** — System prompts (goal and tool schemas) are now hoisted outside the step loop, enabling KV cache prefix sharing across probe steps. This eliminates ~500-1000 tokens of redundant computation per step, significantly reducing per-step latency.

- **Router-First Probe Navigation** — Probe thought chain steps now route through the lightweight router sidecar for tool-selection decisions, freeing the larger worker model for quality-intensive tasks.

- **Spawn Depth Safety** — Nested spawn ancestry is now tracked and enforced via configurable maximum depth limits, preventing infinite recursive spawning during dynamic graph mutations.

- **Default Context Size** — Reduced from 65536 to 32768 tokens for better resource efficiency on consumer hardware.

- **Security Manifesto** — Added comprehensive security and sandbox documentation covering the trust model, isolation boundaries, and threat mitigations.

- **Hardware Configuration Testing** — Added test infrastructure for validating inference backend behavior across different hardware configurations.

## Technical Details

- **ADR-0043**: Two-tier context budget mechanism with dynamic ceiling of `min(nodeCount × 4096, 32000)` characters
- **ADR-0044**: Synthesis-aware context assembly with tiered per-node budgets (recall 8x > validator 6x > action 4x > probe 2x > deterministic 1x)
- **ADR-0045**: Single-slot MCTS evaluation with GBNF-constrained K-candidate generation, heuristic value function (4-signal scoring), and speculation fence using the Proactivity Ladder
- **Dual-Sidecar Spec**: Router (MiniCPM5-1B) + Worker architecture with `CallRouter()`/`CallWorker()` dispatch and transparent fallback via `isRouterAvailable()` health check
