# tzro v1.0.0 Release Notes

**Release Date**: 2026-07-15

---

## ✨ New Features

- **Content-Aware Compaction Engine** — The execution engine now intelligently compacts context during multi-step exploration tasks. Code is never summarized by the AI — it's preserved verbatim or structurally extracted. Only the AI's own reasoning text is compressed, keeping tool outputs faithful to the source. This prevents context window overflow during long exploration chains without sacrificing code accuracy.

- **Goal-Directed File Reading** — When exploring large files during a task, the engine now automatically focuses on sections relevant to the current goal. Small files are returned in full; large files are intelligently summarized against the task objective. This dramatically improves the quality of codebase exploration by preventing important context from being displaced by irrelevant code.

- **Worker Model Synthesis** — Final task summaries are now generated by the larger worker model (64K context window) instead of the lightweight router model. This produces significantly more coherent and comprehensive synthesis of multi-step exploration results.

- **Upgraded Default Model** — The default local model has been upgraded to Agents-A1-4B, delivering improved performance on agentic tasks including tool selection, code understanding, and reasoning quality.

- **AST-Based Symbol Extraction & Anchor Verification** — A new deterministic Symbol Extractor uses pure-Go tree-sitter (`odvcencio/gotreesitter`) to parse every file read during a Probe Node's Thought Chain, emitting `{name, kind, signature, file, line}` tuples into a SQLite Symbol Index. After synthesis, the Symbol Anchor Check diffs referenced identifiers against the Index and triggers a targeted correction pass when >20% are unanchored — eliminating the class of hallucinated type names observed in docgen benchmarks. Ships with 12 embedded grammars (Go, TypeScript, JavaScript, Python, Java, Rust, Dart, C++, C#, Kotlin, Swift, Ruby).

- **Directory Preloading** — Probe Nodes now pre-load source context from target directories before the Thought Chain begins, injecting AST-extracted exported symbols (for Go files) and raw content (for Markdown/text) directly into both the exploration and synthesis phases. A 32K character budget (~8K tokens) prevents context overflow. This eliminates the "routing problem" where probes missed files during exploration because the local model failed to navigate to them.

- **Repo Mapping & Direct Synthesis** — A new `repomap` package generates deterministic AST-based codebase architecture maps. When combined with the new Direct Synthesis mode, Probe Nodes can satisfy tasks with a single-shot inference against pre-compiled context — bypassing the full multi-step Thought Chain entirely for tasks where exploration is unnecessary.

## 🔧 Improvements

- **`.gitignore`-Aware Operations** — Directory operations now respect `.gitignore` patterns, preventing build artifacts and dependency folders from polluting task contexts.

- **Website Redesign** — The documentation site has been rebuilt with interactive architecture visualizations, GitHub integration, and new Privacy Policy and Terms of Service pages.

- **Compaction Reliability** — Compaction is now triggered every 3 steps as a fixed system constraint rather than a planner-configurable parameter. This eliminates a class of context overflow failures caused by planners setting overly aggressive compaction intervals.

- **Default `max_tokens` Enforcement** — Inference calls now enforce a sensible default `max_tokens` value, preventing unbounded generation that could waste local compute and stall the pipeline.

- **Node-Type-Aware Binding Fallbacks** — Dynamic binding resolution now falls back to plain-text format when JSON binding fails, with behavior varying by node type. This makes variable passing between DAG nodes more resilient to malformed upstream outputs.

- **Plan Template Selection** — The router now classifies task categories and selects a structural starter template from a registry. The planner receives this template and makes targeted mutations rather than generating a complete graph from scratch, significantly improving structural reliability for complex task types like documentation generation.

## Technical Details

- New `internal/compactor/` package with `CompactContent`, `CompactSteps`, and `CompactFacts` entry points, plus `CompactEngine` interface with `RouterEngine` and `PassthroughEngine` implementations
- `internal/executor/probe.go` now accepts a `synthesisEngine` parameter, enabling separate inference backends for thought chain steps vs. terminal synthesis
- `internal/tools/filesystem.go` implements `FileReadGoalKey` context propagation from the probe executor to the `read_file` tool
- `internal/inference/model_catalog.go` default worker model changed from Qwopus3.5-4B to Agents-A1-4B
- New `internal/symbols/` package with `ExtractSymbols()` (tree-sitter AST parsing across 12 languages) and `CheckAnchoring()` (post-synthesis hallucination detection)
- New `internal/memory/symbol_index.go` with `InsertSymbol()` and `GetSymbolsForProbe()` for SQLite-backed Symbol Index persistence
- New `internal/executor/probe_preload.go` with `preloadDirectoryContext()` for pre-Thought-Chain source context injection (32K char budget)
- New `internal/repomap/` package with `GenerateRepoMap()` for deterministic AST-based codebase architecture mapping
- New `internal/comparison/conditions.go` with benchmark evaluation conditions for docgen task quality verification
- ADR-0046 documents the structured content-aware compaction design decision
- ADR-0047 documents the AST-based symbol extraction design decision
- ADR-0048 documents the plan template selection and mutation design decision
