# tzro v3.0.0 Release Notes

**Release Date**: 2026-09-24

---

## ✨ New Features

- **System 1 Graph Call Execution** — Execute deterministic multi-step workflows locally as directed acyclic graphs (DAGs). Cloud planners compile graph calls with tool, decision, extraction, and group nodes; tzro executes them in topological order with bounded concurrency (~25ms per decision node vs. ~3,500ms in v1).

- **MCP Server for IDE Integration** — Connect your IDE (Claude Desktop, VS Code, Cursor) directly to tzro via the Model Context Protocol. Run `tzro mcp` to start a JSON-RPC 2.0 server over stdio that exposes graph execution with real-time progress notifications.

- **Laya Decision Daemon** — Sub-50ms local decisions without cloud round-trips. The Laya daemon runs ModernBERT-large (421M params) and answers typed questions — yes/no assertions, multi-option selection, and numerical scoring — in a single non-autoregressive forward pass.

- **GLiNER Zero-Shot Span Extraction** — Extract structured entities (file paths, function names, parameters) from unstructured text without hallucination. The GLiNER worker (150M params, ONNX Runtime) performs span extraction locally, returning matched substrings with byte offsets and confidence scores.

- **Yield/Suspension Protocol** — When a decision node's confidence falls below threshold, execution pauses rather than guessing. The yield envelope preserves all completed work and diagnostics, enabling supervisor agents or human operators to inspect the state and re-plan without re-running finished nodes.

- **Fan-Out Group Nodes** — Process collections in parallel by expanding a template node across an item array. Each sub-evaluation runs with isolated input maps and configurable concurrency limits, with automatic result aggregation.

- **JSON Pointer Data Wiring** — Wire data between nodes using `$ref` pointers (RFC 6901 syntax). Reference upstream node stdout, stderr, exit code, status, or custom data fields in downstream node arguments.

## 🐛 Bug Fixes

- **Group Node Concurrent Map Write** — Fixed a critical race condition where parallel fan-out goroutines shared template input maps, causing runtime panics under concurrent execution.

- **Transitive Blocked Node Propagation** — Fixed false cycle detection errors when failed nodes had transitive dependents. Blocked nodes now correctly increment the processed counter.

- **State Compaction in Decision Pipeline** — The Laya adapter now compacts state to ≤450 tokens before dispatch. Previously, raw uncompacted state was sent directly, risking context window overflow.

- **Concurrent Decision Serialization** — The Laya daemon client now holds its mutex through the entire request-response cycle, preventing interleaved stdin/stdout corruption from concurrent callers.

- **MCP Yield Envelope** — The MCP server now emits structured yield envelopes (matching CLI behavior) instead of raw execution results when graph execution yields.

- **Graph Failure Status** — Overall graph status now correctly reflects `"failed"` when nodes fail or are blocked, instead of always returning `"completed"`.

- **Deterministic Extract Node Input** — Extract nodes now use deterministic key lookup order (`text`, `input`, `content`, `stdout`) instead of Go's randomized map iteration.

## 🔧 Improvements

- **Daemon Self-Healing** — Both the Laya and GLiNER sidecar clients detect broken pipes and automatically restart the daemon process before retrying the request.

- **Close() Resource Cleanup** — The Laya daemon client now closes stdin before killing the process, preventing resource leaks.

- **Documentation Website** — Enhanced version switching and scroll-spy functionality in the documentation site.

- **Enterprise Executive Brief** — Added token optimization executive brief for enterprise AI deployment.

## Technical Details

- **Architecture Decision**: ADR-0095 documents the System 1 / System 2 dual-process cognitive architecture, replacing v1's autonomous generative loops with deterministic DAG execution.
- **New Packages**: `pkg/executor` (DAG engine), `pkg/laya` (decision daemon), `pkg/extractor` (span extraction) — 3 new public packages added.
- **Static Memory**: System 1 components use ~870 MB static footprint with no dynamic KV-cache growth.
- **Test Coverage**: 21 Go test packages passing, including comprehensive unit and integration tests for all new packages.
