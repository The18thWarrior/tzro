# tzro v1.1.0 Release Notes

**Release Date**: 2026-08-11

---

## ✨ New Features

- **Verified Task Execution** — A two-stage quality gate now validates outputs after every task completes. Stage 1 runs a structural pre-check locally. Stage 2 performs a cloud rubric evaluation scoring goal alignment, factual accuracy, coherence, and completeness on a 0–1 scale. Rejected outputs are automatically re-synthesized. When gaps are detected, targeted scatter probes fill missing coverage areas.

- **Plan Template Registry** — Task planning now uses canonical DAG templates instead of generating graphs from scratch. A GBNF-constrained classifier routes each prompt to the best-fit template (explore-only, research, data-analysis, multi-tool), and the planner mutates the template to fit the specific task. This significantly reduces hallucinated node types and improves plan quality.

- **Phase Runner** — Complex tasks can now execute through multiple structured phases within a single node (e.g., explore → analyze → synthesize). Each phase has its own step budget and recovery strategy (skip or backtrack on failure), replacing the prior monolithic probe loop with a more resilient state machine.

- **Neural Embedding Sidecar** — A dedicated embedding process now runs independently from the router and worker sidecars, using the All-MiniLM-L6-v2 model for vector embedding generation. This powers neural similarity search for memory queries, skill matching, and Graph-RAG retrieval without competing for inference resources.

- **Two-Pass Tool Extraction** — Tool parameter extraction now separates reasoning from structured output. Pass 1 uses the worker model for natural-language reasoning about the action. Pass 2 uses the router model with GBNF grammar constraints to extract clean structured parameters. This eliminates failures where a single model must reason and produce valid JSON simultaneously.

- **Deterministic Query Path** — Data analysis prompts now use GBNF-constrained intent extraction to map directly to the query builder, bypassing stochastic parameter extraction entirely. This dramatically improves accuracy for structured data queries.

- **MCP UI Dashboard** — The MCP server now includes a real-time task visualization frontend with DAG graph rendering, node-level detail views (probe, analyze, code, synthesis), and live event streaming via an event buffer system.

- **Web Content Extraction** — New structured content extraction for web pages and Office documents with relevance filtering, image removal, and configurable depth limits.

## 🔧 Improvements

- **Synthesis Quality Hardening** — A 16K synthesis ceiling prevents 4B model degeneration when multiple untruncated recall nodes accumulate excessive context. Proportional budgets are applied when total content exceeds the ceiling.

- **DRY Sampling** — Local model inference now uses Don't Repeat Yourself (DRY) sampling penalties to prevent repetitive phrase loops during synthesis, improving output naturalness.

- **Meta-Commentary Detection** — Outputs containing meta-commentary instead of actual analysis (e.g., "I would analyze..." instead of performing the analysis) are now automatically detected and rejected.

- **Iterative Code Edit Loop** — Code modifications now use an iterative edit loop that targets specific hunks rather than rewriting entire files, improving token efficiency for small changes.

- **Cache ID Hallucination Prevention** — Cache-specific examples are conditionally omitted from prompts when no cache data exists, preventing the local model from fabricating cache IDs.

- **Memory-Gated Router Context** — Pre-flight token truncation and cache envelope size optimization reduce prompt overhead for router inference calls.

- **Foreground Compute Preemption** — User-initiated tasks now preempt background compute to ensure interactive responsiveness.
