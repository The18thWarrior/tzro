# Turn reduction implementation plan

Status: implemented; local suites, three native screens, and a paired replication complete. Last updated: 2026-10-02.

The [implementation plan](../../../.scratch/turn-reduction/implementation_plan.md) turns the [agreed evaluation design](../architecture/turn-reduction-evaluation.md) into 14 vertical slices.
Each slice defines its public interface, a first RED test, minimal GREEN implementation, and further acceptance cases.
Each further acceptance case gets its own RED/GREEN cycle.

The proposed architecture has one verification service behind CLI and MCP adapters.
Repository presets define required commands. Native outcomes, application state, deadlines, and evidence retention remain separate facts in the mandatory summary.
The existing Pi runner remains intact while a new native Antigravity entry point prepares the agreed comparison.

## Slice order

1. One local MCP edit returns an observed native check result.
2. One fake native-client task reaches independent grading.
3. Multi-file preflight rejects complete conflicting batches.
4. Failed or unavailable checks retain valid edits.
5. Write failures report observed Partial Application.
6. One shared operation deadline stops owned work.
7. Independent checks continue and prerequisites block dependents.
8. Active MCP cancellation reaches the running operation.
9. Large failures retain inline primary evidence and complete expansion artifacts when storage succeeds.
10. Ordinary Standard setup exposes the tool; evaluation configuration remains isolated.
11. Simple automation receives a generic bulk-edit helper before task launch.
12. Nine fixtures validate stated behavior across Go, Python, and TypeScript.
13. A native Gemini API guard preserves launch reservations and interruptions.
14. The full fake-client matrix produces the agreed speed, correctness, adoption, and usage report.

## Approved interfaces and authentication

The user approved literal replacement and creation edits, `.tzro/verification.yaml`, a dedicated `tzro bench turn-reduction` entry point, and example fixture subjects.
The user selected `GEMINI_API_KEY` instead of cached-account access. Configure provider `gemini` in isolated client settings and pass the key through the environment.
If `.env` supplies the key, the wrapper loads it explicitly. Credential values stay out of snapshots, traces, and reports.
All complete native screens used isolated client homes and the exact selected model.

The existing paid wrapper requires API credentials and conservative dollar prices.
The native Gemini API mode must preserve prior accounting while reporting unknown monetary evidence truthfully.
A task-launch allowance does not establish a hard monetary ceiling or bound every internal provider retry.

Independent grading uses the remaining whole-task deadline and contributes to Verified Completion Time.
Final grading receipts remain separate from in-task verification and tool adoption.
MCP cancellation may abandon response delivery, so local retention is best effort and no delayed result channel is introduced.

## Current scope and validation

The production verification service, CLI, MCP adapter, and ordinary installation are implemented.
The native benchmark replaces the historical custom Gemini REST loop.
Its full scripted-client matrix passes all 27 cells through the real product and independent graders.
Fixture validation covers every broken starting state and reference solution.

The [evidence audit](../bugs/turn-reduction-evidence-audit.md) records the repaired grading and measurement gaps.
The [native screen results](../architecture/turn-reduction-screen-results.md) report 99/99 correct comparison tasks across three screens and a paired replication.
The explicit-guidance screen passed the agreed 20% speed gate with successful production MCP calls on 9/9 Tzro tasks.
The paired replication also passed, with nine successful production MCP calls and 46.71% lower time than Simple.
The user requested explicit AGENTS.md guidance after low tool adoption.
The optional `--tzro-guidance` input freezes and labels this separate experiment without changing ordinary product installation.
