# Verified Task Execution for T4+ Codegen

T4+ codegen tasks can produce syntactically valid but semantically broken code that passes both the Compilation Gate (compiles) and the Spec Compliance Gate (has the required methods). In Benchmark Run 17, `create_query_builder` (T5) scored 2.0 — the generated Go code compiled and had all required functions, but `Limit`/`Offset` rendering failed for numbers > 9, `UPDATE` dropped arguments, and `INSERT` generated invalid SQL.

We extend Verified Task Execution (ADR-0067) to T4+ codegen tasks. After the local model generates code and passes existing gates, a cloud model reviews the generated code against the original task spec. On rejection, the entire codegen task is regenerated by the cloud model (full regeneration, not surgical correction). T1–T3 codegen is excluded — these tiers scored 5.0 across the board in Run 17 and the cloud review cost is not justified.

## Considered Options

- **Unit test generation + sandbox execution**: Rejected — building an execution sandbox adds a new failure surface disproportionate to the problem. Covering a benchmark edge case is not a valid scenario to build sandbox infrastructure.
- **Surgical correction (Edit Loop hunks)**: Rejected for now — assumes the cloud model can reliably identify broken code sections from review alone without running the code. Full regeneration is simpler. Can revisit with more data on rejection patterns.
- **Line-count-based trigger**: Rejected — adds a measurement step and doesn't correlate with codegen difficulty better than the tier classification already computed at intake.

## Consequences

- T4+ codegen tasks incur one additional cloud inference call for review. For rejected tasks, a second cloud call for full regeneration. Marginal cost increase (~$0.02–0.05 per reviewed task).
- T1–T3 codegen remains fully local, preserving the cost profile for the majority of codegen tasks.
- The VTE pipeline for codegen has no Recall Node — the cloud reviewer receives the generated code + original spec only, not exploration context. This is sufficient for code review but means the cloud model regenerates from the spec alone, not from exploration evidence.
