# AgenticOS Jumpdrive Website Positioning

The public website previously positioned tzro as a "Complementary Agentic Companion" and "Local Offload Engine" — subordinate language that framed it as a sidecar to a primary cloud agent. We're pivoting to "Agentic Operating System" as the structural identity and "The Jumpdrive for AI Agents" as the website metaphor.

"Framework" was rejected because the market is saturated with agent frameworks (LangChain, CrewAI, AutoGen, Semantic Kernel) and that label invites commodity comparisons. "Agentic OS" reframes the conversation: tzro is not a library you import — it's a runtime you plug your agent into, with a kernel, scheduler, filesystem, memory, daemons, and permission system.

"Jumpdrive" was chosen over literal alternatives ("Portable OS", plain "Agentic OS") because it's ownable, visually evocative, and conveys all three value propositions simultaneously: instant activation (one MCP config block), completeness (full OS inside), and portability (carry your `tzro.db` between machines). "Jumpdrive" is a website/marketing metaphor only — it does not enter the CONTEXT.md glossary or codebase vocabulary.

The website exposes two parallel onramps: **Plug In (MCP)** for developers who already have an agent host and want to give it a jumpdrive, and **Build On (Framework)** for developers embedding tzro directly into Go applications. Both lead to the same underlying OS. An interactive OS Architecture Diagram serves as the page's navigation spine, mapping classical OS primitives to tzro equivalents and linking to interactive playgrounds and capability cards.
