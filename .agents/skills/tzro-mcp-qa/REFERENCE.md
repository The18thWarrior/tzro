# tzro MCP QA Reference Guide

This reference guide provides standard diagnostic procedures, edge case verification checklists, and database queries for validating the `tzro-mcp` integration.

## 1. Dynamic QA Verification Checklist

Verify that the `tzro-mcp` integration meets these key criteria:

- [ ] **Spawn & Lifecycle**: Spawned MCP child processes terminate cleanly when the parent agent exits or the `tzro` daemon is stopped. (No zombie processes left running).
- [ ] **Tool Registration**: Client tools registered via `tzro_register_client_tools` show up with correct JSON schemas.
- [ ] **State Durability**: Task state is written to SQLite at every pause/resume transition. Restarting the client/daemon should NOT lose current task status.
- [ ] **Pause/Resume Integrity**: Task enters `waiting_for_client` state during a client tool step, executes the tool locally in the host, submits result via `tzro_client_tool_submit`, and transitions back to executing cleanly.
- [ ] **Probe Compaction**: For Probe nodes, confirm that intermediate thoughts are compacted every 3 steps, and summaries are persisted in the `summaries` table.
- [ ] **Terminal Synthesis**: The Probe node writes its final goal-directed synthesis back to the database as the node's output.

## 2. SQLite Diagnostic Queries

Inspect the SQLite database (`tzro.db`) during execution to verify correct state recording.

### Check Task Graph and Status
```sql
-- View all cached task graphs and execution status
SELECT cache_id, json_extract(raw_payload, '$.status') as status, datetime(created_at, 'unixepoch', 'localtime') as created 
FROM disk_cache 
WHERE cache_id LIKE 'graph_%';
```

### Inspect Probe Node Thoughts & Steps
```sql
-- Retrieve all thought steps for a given probe node run
SELECT step_index, thought, tool_name, tool_args, tool_output
FROM thought_chain
WHERE probe_id = 'YOUR_PROBE_ID'
ORDER BY step_index ASC;
```

### Inspect Compaction Summaries
```sql
-- Retrieve all rolling summaries generated by compaction
SELECT step_range, summary, datetime(created_at, 'unixepoch', 'localtime') as created
FROM thought_chain_summaries
WHERE probe_id = 'YOUR_PROBE_ID'
ORDER BY id ASC;
```

### Check Registered Client Tools
```sql
-- Retrieve registered tools list payload from the database
SELECT raw_payload 
FROM disk_cache 
WHERE cache_id = 'registered_client_tools';
```

## 3. Edge Cases to Probe

When running dynamic QA, proactively trigger and verify the system's resilience to these conditions:

1. **Host Client Crash**: Force kill the Python host script mid-task. Verify the `tzro` daemon keeps the task state locked in SQLite, ready for `tzro_resume`.
2. **Missing Environment Variables**: Test tool parameter resolution when delegated secrets prefixed with `$` refer to missing host variables.
3. **Database Locks**: Run multiple concurrent tool submissions using parallel client tools. Verify SQLite avoids "database is locked" or write serialization errors by utilizing WAL mode and retry-on-busy logic.
4. **Failed Tool Execution**: Return an error message or empty output from the client tool and verify the executor marks the step appropriately rather than hanging indefinitely.
